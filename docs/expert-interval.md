# 辅助 AI 推理间隔

资产面板的“辅助 AI”菜单控制 RTMW 与 Human-Art ViTPose 两个辅助专家的调用频率。
基础 HRNet/MotionBERT、逐帧光流、原视频帧率和最终动画时间轴保持原来的逐帧路径。
它不是视频抽帧，也不会把未调用辅助专家的帧标成手工可信关键帧。

| 选择 | 行为 |
| --- | --- |
| 逐帧 | 两个可用辅助专家每帧检查，作为对照 |
| 每 2 帧 | 平稳时距离上次调用至少 2 帧后检查；Studio 初始试用设置 |
| 每 3 帧 | 平稳时距离上次调用至少 3 帧后检查 |
| 自动 | 起初每 2 帧，连续平稳约四分之一秒后每 3 帧；遇到风险加密 |

低置信度或缺失关节、按身体尺寸归一化后的快速/突变运动、光流失效会立即触发检查。
专家冲突或无结果会使后续帧继续密集检查。风险清除后仍保持约 100 毫秒的密集检查，
避免在阈值附近反复切换。阈值是保守启发式，尚不是基于标注视频校准的准确率保证。

第一次进入视频、时间不连续时也会密集检查。每个视角使用独立调度状态，
即使多视角复用同一组 GPU 模型，也不会沿用上一视角的速度或调度相位。
跳过的专家不复用旧预测参与当前帧融合，当前基础观测继续决定该帧结果。
这一步不更改捕捉后的手工锁定、排除和区间修复层。

## 命令行与诊断

单视角 `mmpose_adapter.py` 和多视角 `multiview_pipeline.py` 都接受：

```text
--expert-interval 1
--expert-interval 2
--expert-interval 3
--expert-interval auto
```

省略该参数保持旧的 `--quality` 调度，方便现有脚本兼容。
明确指定间隔会覆盖 balanced/maximum 的辅助专家调度；`--quality fast` 仍禁用辅助专家。
界面选项只影响下一次捕捉，捕捉过程中不能修改；当前选择保留在本次应用会话内。

每份 `pose_sequence.json` 旁写出 `expert-schedule.json`，多视角分别在各视角目录下记录。
报告包含帧数、帧率、模式、实际尝试/成功次数，以及逐帧运行、跳过、不可用、无结果和补算原因。
`source_frame_count_hint` 是视频容器报告的帧数；`output_frames` 才是本次实际输出帧数。
backend 中 `full` 只用于确实每个输出帧都有该专家结果的情况，否则使用 `adaptive`。

间隔不保证按比例提速：基础动捕、VSR、分割等仍有逐帧工作；困难视频也可能一直触发补算。
需要用同一视频比较逐帧与间隔模式的实际耗时、专家调用比例、快速动作细节和漂移，
再决定最终默认值。自动化测试验证调度与数据合同，不代替真实 GPU 视频的质量验收。
