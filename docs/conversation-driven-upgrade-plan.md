# Conversation-Driven Stability Upgrade Plan

This document records the current product direction and the concrete issues raised during this conversation. It is intentionally detailed so later Codex passes can continue without re-deriving the same context.

## Product direction

YoloWorkBench should become a video-first annotation workbench while preserving image tools as secondary workflows.

The intended default workflow is now:

```text
Open workspace
  ↓
Add video
  ↓
Decode frames on demand from the video
  ↓
Annotate timestamp records directly
  ↓
Use voice / hand / arm controls when useful
  ↓
Keep image pool and image box labeling available, but not primary
```

Frames should not be extracted into `image_pool` merely to annotate them. Video annotations should live as timestamp manifests under `workspace/video_annotations` or the manifest-configured equivalent.

## User complaints captured so far

### 1. Old video workflow was wrong

Previous workflow:

```text
Video → screenshots → image annotation
```

Problem: this creates unnecessary files and makes video annotation feel like a workaround.

New target:

```text
Video → direct timestamp annotation
```

Status: direct video annotation has been implemented on the stacked video branch.

### 2. Images must remain supported but are no longer primary

The image workflows should stay available:

- Image Pool
- Image Box Label
- Dataset Review
- Dataset Prep
- Auto Label
- Crop / Mask / Merge

But the application shell and documentation should present Video Label as the primary entry point.

Status: implemented through the tool registry and video-first ordering.

### 3. Gesture control should not depend on perfect hand detection

The user may not make accurate hand gestures. The system must support larger motions such as forearm or full-arm movement.

Implemented mapping:

| Motion | Command |
|---|---|
| Arm left | Previous video step |
| Arm right | Next video step |
| Arm up | Copy previous boxes |
| Arm down | Mark current frame reviewed |
| Point + pinch | Draw box on calibrated canvas |

The system uses shoulder, elbow, and wrist pose landmarks so imperfect hand classification does not fully break controls.

### 4. Camera may not be front-facing

The camera may view the desk or interaction plane at an angle. AprilTag calibration should correct pointing and pinch coordinates.

Implemented:

- Printable AprilTag 36h11 sheet with IDs 0, 1, 2, 3.
- OpenCV detection endpoint.
- Four-point homography.
- Manual four-corner fallback.

Important limitation: homography corrects the plane only. Hands above the plane still have parallax error.

### 5. Voice control should coexist with gestures

Voice and gestures should use the same command contract, not separate feature-specific logic.

Implemented:

- Canonical `CommandEnvelope`.
- Command arbiter with lock, confidence, cooldown, and destructive command confirmation.
- Browser speech recognition adapter.
- Chinese and English command parser.

Future: add a local Whisper / whisper.cpp adapter so the desktop build does not depend on browser speech support.

### 6. Grid auto-centering is too aggressive

User intent:

- A/D keyboard navigation may auto-reveal or center the target item.
- Mouse click should not auto-center the grid.

Problem: when clicking while visually scanning the grid, the grid unexpectedly jumps and disrupts visual search.

Implemented in this branch:

- Gallery reveal requests are only generated by valid A/D key events.
- Pointer selection cancels pending keyboard reveal.
- Ctrl/Alt/Meta and text-input targets do not trigger reveal.

### 7. Box Label shortcut settings are lost

Observed complaint: project/session JSON often loses shortcuts.

Probable causes fixed in this branch:

- Missing shortcut fields were being treated like an explicit empty shortcut layout.
- Box Label could emit a shortcut-save before workspace session hydration completed.
- Shortcut changes were not mirrored immediately to the local per-workspace fallback store.

New rule:

- Missing shortcut session means “unknown / not hydrated,” not “all shortcuts cleared.”
- Explicit empty shortcut arrays still mean empty shortcuts.
- Remote session write starts only after hydration or user mutation.
- Shortcut changes are also saved into local storage as a fast fallback.

### 8. Mark Junk should remove items immediately

Problem: Mark Junk did not remove the current image from Box Label immediately.

Target behavior:

- The current or selected images disappear immediately from the labeling queue.
- The grid should not flash or hard-reset.
- The following thumbnails should fill the empty slot with a short compaction animation.

Implemented in this branch:

- Mark Junk optimistically updates metadata and removes target entries from the in-memory queue before backend writes complete.
- Selection is cleared after junking.
- Current index is clamped to the next available image.
- If the backend write fails, entries are restored and metadata is reloaded.
- Undo Junk reloads entries after restoring links.
- Gallery FLIP animation moves surviving thumbnails into their new positions.

## Architecture principles going forward

### Separate input from actions

Voice, hand gestures, arm motion, keyboard, and UI buttons should produce the same canonical commands.

Feature pages should not know whether a command came from speech, a gesture, or a button.

### Keep workspace state explicit

Workspace state should move toward explicit versioned manifests and small focused session records.

Do not overload one JSON file with everything. Use separate namespaces:

```text
workspace/workspace.json         project identity and paths
workspace/session.json           UI session and resumable state
workspace/video_annotations/*    video timestamp annotations
workspace/logs/*                 event and operation logs
.cache/*                         disposable cache only
```

### Treat UI animation as a contract

For heavy annotation workflows, layout stability matters. Avoid surprising jumps.

Rules:

- Mouse selection should preserve visual context.
- Keyboard navigation may reveal target context.
- Bulk removal should animate compaction.
- Restore-scroll behavior should be explicit and one-shot.

### Prefer optimistic UI with rollback

Actions that update metadata should update the UI immediately when safe, then write backend state.

If the backend write fails, roll back the optimistic change and surface the error.

## Box Label stability hardening pass

Branch: `feature/box-label-stability-hardening` (stacked on `feature/box-label-stability-pass`).

### What was fixed

**Shortcut/session persistence race (`useBoxLabelClasses.ts`)**

The sync effect that propagates shortcut and fixed-box state to the session file was
gated on `!shortcutSlotsHydratedRef.current && !fixedBoxSlotsHydratedRef.current`.
This allowed the effect to fire when only fixed-box slots had been hydrated from the
session (but shortcuts had not), writing unvalidated localStorage shortcuts back into
`session.json` — erasing the "no shortcuts" state the session file deliberately had.

Fix: replaced the per-field hydration flags with a single `userMutatedRef`. The sync
effect now only runs when an explicit user action (dropdown change, draw-to-record)
triggered the state change. Hydration effects no longer set this flag, so they never
propagate to the session.

**`markJunk` rollback missing `currentIndex` restore (`useBoxLabel.ts`)**

When the backend write for Mark Junk failed, `allEntries` was restored but
`currentIndex` was not. The gallery and preview showed a mismatched image after rollback.

Fix: save `previousIndex` before the optimistic update and restore it in the catch block.

**`savePoolLabelSession` — `poolLabelSavedAt` not always written (`session.ts`)**

The timestamp was only written when shortcut, fixed-box, or tool-state fields were
included. Navigation-only saves (image advance by A/D or mouse click) did not record a
timestamp, making it hard to diagnose session-write ordering bugs.

Fix: `poolLabelSavedAt` is now always included in every write. A
`poolLabelSessionVersion: 1` field is also written to support future migrations.

**`computePostRemovalIndex` extracted as a pure function**

The index-clamping logic inside `markJunk` was extracted to a module-level function
and exported for unit testing. `markJunk` now calls this helper directly.

### Tests added or extended

- `session.test.ts`: null vs empty-array semantics for missing/explicit shortcut
  fields; partial array normalisation; negative classId rejection; fixed-box missing
  field; explicit empty fixed-box array.
- `galleryNavigation.test.ts`: textarea/select targets; uppercase A/D; unrelated keys;
  single-item list; stale-reveal cancellation contract.
- `junkRemoval.test.ts` (new): eight pure tests for `computePostRemovalIndex` covering
  current-item removed, last-item removed, all-items removed, multi-selection, and
  non-current removals from before and after the cursor.

### What remains fragile

- **Session write race**: `savePoolLabelSession` reads the full session file before
  writing (read-modify-write). Two concurrent writes within the 500 ms debounce window
  can still clobber each other. A proper fix requires backend support for field-level
  partial writes or optimistic-concurrency tokens. Not attempted in this pass.
- **`sortedEntries` vs `entries` index contract**: `currentIndex` is relative to
  `sortedEntries` but `computePostRemovalIndex` operates on the unsorted `entries`. In
  practice both are in the same order because `allEntries` is pre-sorted. If that
  invariant ever breaks (future filter or order change), the index calculation will be
  wrong. A comment has been added noting the fragility.
- **Undo Junk does not restore scroll position**: after `undoJunk` calls `load()` with
  `background: true`, the scroll anchor is not set. The restored image is findable but
  the gallery may not scroll to it.
- **Prefers-reduced-motion FLIP**: the compaction animation respects
  `prefers-reduced-motion`, but the check happens at runtime each time. Changing the
  OS preference while the animation is in progress is not handled.

### Known limitation discovered during implementation

`py_compile` passes for touched Python modules but `python -m unittest discover` fails
with `ModuleNotFoundError: No module named 'backend'`. This is a pre-existing
environment issue — the repo root is not on `sys.path` when running from a subdirectory.
Running `PYTHONPATH=$(pwd) python -m unittest discover -s tests -p "test_*.py"` from
the repo root resolves it. No Python files were changed in this branch pass.
